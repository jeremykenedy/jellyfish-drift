# Jellyfish Drift 1.1.0

Jellyfish Drift now renders curved translucent bells, folded oral arms and continuous trailing filaments instead of deforming whole jellyfish pictures. Moon jelly, sea nettle and purple-striped jelly have distinct shapes, fringes and color absorption, with independent contraction phases and drift.

## Upgrade guide

From 1.0.0, install the signed `jellyfish-drift.apk` over the existing package. Do not uninstall first: an ordinary same-package, same-signer update preserves the six visual preferences. No migration, new permission, online account or runtime download is required. Restart the preview or screensaver to load the new renderer.

```sh
firetv-screensavers --install=jellyfish-drift
```

Standalone users can run `python3 install.py --serial TV_IP:5555`, or verify the downloaded checksum and install manually:

```sh
shasum -a 256 -c jellyfish-drift.apk.sha256
adb -s TV_IP:5555 install -r jellyfish-drift.apk
```

Selecting Jellyfish Drift remains a separate action. Installation does not change the selected screensaver, timeouts or sleep settings. Android 6.0/API 23 remains the minimum. Version 1.1 explicitly requires OpenGL ES 2.0; verify that capability before updating a custom device. Existing per-setting random choices and randomize-all values keep their meanings. No cache, worker or database steps are needed.

For rollback, save the six current choices, uninstall 1.1.0 and install the original signed 1.0.0 APK, then reapply those choices. Uninstalling removes app preferences; a normal version-code downgrade is rejected. This repository has no release older than 1.0.0.

## Breaking changes

The manifest now requires OpenGL ES 2.0, which 1.0 declared optional. A custom device without that capability cannot run the new renderer and should remain on 1.0. Existing Android TV/Fire TV targets in the verification matrix provide it. Package, provider keys, accepted values, permissions and minimum Android API remain unchanged. The visual interpretation changes substantially: the renderer uses curved scene geometry rather than whole-animal image cards. Folded oral-arm geometry remains angular in places; this is an original rendered scene, not recorded footage or a numerical volume simulation.

## Major changes

- Curved contracting bells with transmitted light and depth-dependent species color.
- Short moon-jelly fringes and four central arms, long nettle tentacles, and violet-striped bells.
- Continuous camera-facing filament sections following 3D centerlines, reducing edge-on dotted appearance.
- Independent contraction phases, tilted orientations and subtle water motion.
- Deep and bright water, overhead rays, density 3/7/11/17/25 and slow/natural/fast movement.

## Minor changes and fixes

- Preserve the six visual setting keys and original production signer.
- Soften oral-fold highlights and averaged normals while retaining folded geometry.
- Bundle the complete Apache license and project NOTICE in a remote-accessible offline Credits dialog.
- Refresh native previews, animated theme banners, provider documentation and capture provenance.
- Enforce actual Java formatting and 100% line/branch coverage for owned testable settings and geometry logic.

## Verification and limits

The indexed-buffer candidate is version 1.1.0/code 2, SHA-256 `e804871a9393ec8e564c1e8c2458a904841020debdd0e084e0b8d90134ee2123`, 1,271,121 bytes. It preserves the original triangle geometry and shader/material assets while sharing vertices and keeping meshes on the GPU. Current host tests, formatting, coverage, privacy and documentation checks pass. Its native and physical gates are pending. The earlier c065 APK passed functional routes but produced only 6.53 presents/second in the physical 25-nettle sample; that result blocks publication until a corrected artifact passes.

No native 4K, physical Google TV, automatic idle, sustained thermal or power claim is made. [Device verification](../VERIFICATION.md) records tested scope and [host integration](../INTEGRATION.md) provides package, signer, provider and artifact details. There are no ads, analytics, tracking, crash reporting or runtime network permission.
