# Jellyfish Drift 2.0.0

Version 2.0 replaces the generated jellyfish renderer with two licensed, silent recordings: Blue aquarium and Deep ocean. This is a major release because the effective settings contract changes. The package, production signer, Android API floor, and all six saved raw preference values remain stable.

## Upgrade guide

The supported public upgrade path is from v1.0.0. Android 6.0/API 23 remains the minimum; the Android version code increases from 1 to 4. Python 3 and ADB are needed only for the standalone installer. No runtime dependency, account, network permission, or content download is added.

With the target TV connected, run:

```bash
python3 install.py --serial TV_IP:5555
```

The installer downloads the published APK and checksum and replaces the existing package. Keep the app installed during the upgrade to preserve preferences. No database migration, environment change, cache clear, or worker restart is needed. Installation does not change the selected Dream or system timers.

Open Jellyfish Drift settings, choose the desired recording and playback speed, and try Preview before selecting it as the active screensaver. Existing density, species, and light-ray values remain stored but no longer change the scene. Host editors should use the current three-row schema rather than cached version 1 controls.

To stop using version 2, select another installed screensaver while keeping Jellyfish Drift and its preferences. Android can reject signed APK downgrades; a data-preserving downgrade to version 1 is not promised. Uninstalling deletes saved app data. Keep a copy of important settings before any removal.

## Breaking changes

| Previous behavior | Version 2 behavior | Upgrade action |
| --- | --- | --- |
| Generated creatures, configurable density, species, and rays | Fixed animals and lighting from each recording | Choose a filmed scene; do not expect the three preserved legacy values to affect it |
| Dark and light generated water | Deep ocean Crossota and Blue aquarium Aurelia recordings | Recheck the selected recording |
| Simulated swimming speed | Actual playback at 0.9x, 1x, or 1.25x | Select the preferred playback rate |
| Randomization included generated creature controls | Randomization chooses only scene and playback speed | Update host option descriptions |

The six raw provider values remain validated and readable. Only scene, speed, and randomization appear in the effective schema and native settings.

## Major changes

Both Preview and DreamService use the same offline MediaPlayer lifecycle, with 1080p H264 and a 720p fallback. Playback stops and releases resources when the view stops or its surface is destroyed. Normal task resume restores playback. No words, agency titles, logos, or watermarks are rendered in the selected scenes.

Credits and full licenses are available offline in native settings. Aurelia footage and derived images retain CC BY-SA 4.0; credited NOAA footage uses its source public-domain terms. Application code remains Apache-2.0.

## Minor changes and fixes

Provider updates return success only after a synchronous saved-preference commit. Native old/new process-death comparisons passed, but did not reproduce the earlier transition failure. Device logs identified low-memory eviction of a background provider; the functional configuration gate uses the normal foreground Settings route.

Formatter paths and coverage thresholds now check the actual project files and require full line and branch coverage for the two pure settings classes. The installer retains checksum and download validation.

## Verification and limits

Local tests, privacy, style, documentation, and coverage checks passed. The pure Java classes cover 25/25 lines and 34/34 branches. Twenty-four installer tests passed. Actual Android TV API 34 checks covered remote scene/speed selection, Preview, resume, and offline Credits. Close-button activation used a native tap; Back closure also passed.

The final signed code 4 artifact passed four actual non-test Dream cases on a physical Fire TV API 30. Minimum settled presentation windows were 26.904/36.716 presents/s for Blue aquarium at 0.9x/1.25x and 26.904/37.241 for Deep ocean. No screen recording ran during those measurements. Fresh app, UI, OS, external-file, guard/VPN, and sleep state were restored. The installed Aquarium Live build had no readable provider, so its raw preferences were not verified.

The recordings repeat every 16 or approximately 19 seconds, with editorial dissolves. Crossota also has a source camera-view transition. These are recorded animals, not an interactive simulation. Physical Google TV, sustained thermal behavior, automatic idle activation across vendors, decoder failure fallback, and native 4K source detail remain unverified. Functional and moving reviews do not imply owner visual acceptance.
